CreditDoc-AI — Scanned documents, structured extraction and RAG

Document AI · OCR · LLM · Grounded Q&A

2026

PDF parsers fail on scanned documents: there is no text left, only an image. Yet most of a bank's digitised paper files are exactly that. CreditDoc-AI starts from the image, cleans it, runs OCR, rebuilds the tables, then extracts validated data. A question-answering interface then queries the document and cites its sources. Everything runs locally, so no document leaves the premises.

Validated JSONPydantic schema per sector
Grounded RAGpage citation, refusal if absent
100% localno external API call
  • Image pipeline. OpenCV preprocessing (deskew, denoise, binarise), then OCR. Tables are rebuilt from the position of the words.
  • Two-layer extraction. Label rules first, tolerant to OCR errors. The LLM only runs second, with JSON-schema constrained output, and only for the fields left empty.
  • Checks before use. Pydantic validation, provenance for every value, and inconsistent amounts flagged rather than silently corrected.
  • RAG over the document. Hybrid search, answers written only from the retrieved passages, page citation, explicit refusal when the information is absent.

Tech: Python · OpenCV · OCR · Ollama · Pydantic · Streamlit

News-Radar — Semantic search and RAG over a live corpus

RAG · pgvector · Local embeddings · FastAPI

2026

A platform that continuously collects AI and data engineering publications, makes them searchable by meaning rather than keywords, and lets you query them in conversation. No API key, no cost per request.

~1,000articles indexed
384 dimslocal embeddings, pgvector
30 minautomatic ingestion cycle
  • Ingestion pipeline. Scheduled RSS collection, HTML cleaning, deduplication by URL hash and a uniqueness constraint. Running it again creates no duplicates.
  • Semantic search. Embeddings computed locally, stored in PostgreSQL with pgvector, cosine distance search. A query phrased differently still finds the right article.
  • RAG chatbot. Two modes: grounded on the retrieved articles with their sources, or general knowledge. The grounded mode declines to answer outside the corpus.
  • API and interface. FastAPI backend with about fifteen routes, containerised PostgreSQL, web interface served by the API.

Tech: Python · FastAPI · PostgreSQL / pgvector · fastembed · Ollama · Docker

BIAT — Financial Document Intelligence & Credit Risk

Banque Internationale Arabe de Tunisie · AI Engineer & Data Scientist — Final-year project

Feb – Jul 2026

Automating financial-statement processing to support credit risk analysis. Financial statements published as PDFs require substantial extraction, cleaning and preparation before they can be used for financial analysis. I built a pipeline combining Document AI, OCR, data processing and LLMs, from document validation through to generating a summary that supports credit risk analysis.

4 statementsbalance sheet, income, equity, cash flow
4 ratio familiesliquidity, solvency, profitability, leverage
N / N-1year-on-year comparison
  • Document validation. Checking the nature of the document to confirm it is indeed a company's financial statements before any further processing.
  • Extraction & structuring. Extracting financial tables from the statements filed as PDFs with the CMF, the Tunisian market regulator, using Docling and OCR: balance sheet, equity and liabilities, income statement and cash-flow statement. The data is then structured and stored in MongoDB.
  • Data cleaning & verification. Cleaning, normalising and checking the extracted data to surface OCR errors, inconsistent values and items that need review before analysis.
  • Financial & credit analysis. A decision-support application built with Streamlit, computing liquidity, solvency, profitability and leverage ratios and comparing the current year against the previous one.
  • Analysis summary generation. An LLM generates a reasoned summary from the available data and ratios, with several levels of assessment: favourable, reserved, unfavourable or needs further review. Previous assessments stay available. The final decision remains with the analyst.
  • Industrialisation. Pipeline orchestrated with n8n and containerised with Docker.

Tech: Python · Docling / OCR · MongoDB · Streamlit · LLM · n8n · Docker

CreditGuard — Explainable & Monitored Credit Scoring

Credit risk · Probability of default

2026

A scoring system that estimates default risk while also providing an explanation of its predictions and indicators for monitoring the model. The aim is to combine predictive performance, interpretability and tracking of model stability.

0.757AUC
SHAPprediction explanation
PSI + KSdrift surveillance
  • Probability-of-default model. A LightGBM model estimating an applicant's probability of default.
  • Explainability via SHAP. Analysis of the features contributing to each prediction, making the model's output more interpretable and easier to review.

FraudGuard — Fraud Detection & AML/CFT Monitoring

Fraud · Financial Crime · Transaction Monitoring

2026

A transaction-monitoring system combining machine learning with business rules. The project separates the detection of transaction behaviour associated with fraud from a rule engine meant to flag scenarios requiring an AML/CFT review, then centralises the results in a single alert queue for the analyst.

0.89PR-AUC
0.82F1 score
6.4Mtransactions · 0.13% fraud
  • Fraud detection. An XGBoost model trained on a heavily imbalanced dataset. The decision threshold is tuned on the trade-off between missed frauds and false alerts rather than left arbitrarily at 0.5.
  • Transaction monitoring. A rule engine covering transaction velocity, structuring and certain account patterns, with BLOCK / REVIEW / ALLOW action levels.
  • Explainability. SHAP is used to identify the main features contributing to the alerts raised by the fraud model.
  • Data leakage detected and fixed. An early version reached PR-AUC 0.9998 by using features posterior to the transaction, and therefore unavailable at decision time. Those features were removed to build a more realistic evaluation, based only on information available before the transaction.

Tech: Python · XGBoost · SHAP · pandas · Streamlit

Dysphonia detection from voice recordings

Audio signal processing · Classification · Supervised academic project

2024

First-year engineering project carried out for the Salah Azaïez Institute in Tunis. Diagnosing dysphonia takes long sessions, and tracking a patient's improvement is hard to measure objectively. The goal was to extract measurable indicators from simple sustained-vowel recordings.

3 vowelssustained /a/, /i/, /u/
MFCC+ spectral centroid, zero-crossing rate
2 modelsRandom Forest and KNN compared
  • Data. Recordings from the public Saarbruecken Voice Database: healthy and dysphonic voices, men and women, three pitch levels.
  • Preparation. A single dataset built from scattered files, with duration, sample rate, vowel, pitch, gender and class. CRISP-DM method.
  • Audio features. MFCC coefficients, spectral centroid and zero-crossing rate, chosen to describe voice quality rather than spoken content.
  • Results. Random Forest beats KNN on both classes: precision 0.73 against 0.66 on healthy voices, 0.57 against 0.46 on pathological ones.
  • Stated limitation. Scores stay lower on the pathological class, which is under-represented. That is the first thing to fix before any clinical use.

Tech: Python · librosa · scikit-learn · Random Forest · KNN · pandas

AidBridge — Visual assistance and sign language recognition

Computer vision · Deep Learning · Academic team project (pair)

2025

Second-year engineering project, supervised at ENSIT. A prototype assistant for people with visual impairments, Alzheimer's disease or speech loss: it reads aloud the objects in front of the camera and translates sign language gestures into text.

  • Object detection. YOLOv8m pretrained on COCO (80 classes), chosen for its balance between speed and accuracy. Detected objects are announced through text-to-speech, run in a separate thread so the video stream never blocks.
  • Sign language. A video dataset we recorded ourselves, body and hand landmarks extracted with MediaPipe Holistic, then a stacked LSTM network that classifies each gesture sequence.

Tech: Python · OpenCV · Ultralytics YOLOv8 · MediaPipe · TensorFlow / Keras · pyttsx3
